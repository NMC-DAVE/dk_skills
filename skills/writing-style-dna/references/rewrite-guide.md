# 写作与改写流程细则

本文件是模式 B（按风格写作）和模式 C（按风格改写）的操作依据。两种模式共用"前置读取"和"信息守恒"，先讲共性，再分流程。

## 〇、前置读取（两种模式共用）

1. 读全部档案：`风格DNA.md` + `语言DNA.md` + `结构模板.md` + `立场与认知.md` + `排版规范.md`，一份不跳。
2. 从 `raw/` 选 2-3 篇与本次任务体裁、场合最接近的样文通读（登记表筛选；语料 ≤3 篇时全读）。读完先向自己复述：这几篇的共同语感是什么、开头怎么起、部署怎么分条、口径有哪些——说不出来就再读一遍。
3. 无档案时走"临时校准"快速通道（见 SKILL.md 第五节），精读样文后临场提炼 8-12 条要点。

## 一、信息守恒（最高优先级，两种模式共用）

工作文档的容错率极低。写作时内容点只能来自用户提供的材料；改写时原稿信息一个都不能丢、不能多、不能变。

### 绝不能动的信息

- 数字、百分比、金额、时长、次数、日期、文号
- 人名、机构名、职务、地名
- 引语、政策原文、上级批示的表述
- 决议事项、任务清单、责任分工、时限
- 文种（改写不得把"请示"改写成"报告"的写法）

### 表态等级表（口径红线）

表态词有强度梯度，改写时只能平移、不得升降。原稿用哪一级就保留哪一级；按档案风格润色时，在同级内替换。

| 等级 | 词例 | 改写红线 |
| - | - | - |
| 同意（强→弱） | 同意 > 原则同意 > 原则上同意 > 拟同意 | "原则同意"不得改成"同意"；"拟同意"不得改成"同意" |
| 拟办 | 拟 / 建议 / 请 / 商 | "拟"不得改成"决定" |
| 要求强度 | 必须 > 要 / 须 > 应当 / 应 > 力争 / 争取 > 希望 / 鼓励 | "力争"不得改成"确保"；"要"不得升级为"必须"或降级为"希望" |
| 时间 | 定于 > 拟于 / 计划于 > 考虑 | "拟于"不得改成"定于" |
| 评价 | 全面完成 > 基本完成 > 部分完成 | "基本完成"不得写成"全面完成" |
| 问题分寸 | 存在短板 > 仍有差距 > 有待提升 | 只能同级替换，不得避重就轻或加重 |

拿不准两词是否同级时，保留原词。

### 守恒核验办法

改写完成后，把改写前列出的信息点清单逐项与成稿对照：每个数字、日期、人名、事项、表态都能在原稿中指出出处；成稿里每个新增实词都能指出来源（用户材料或用户本次指令）。指不出就撤销。

## 二、写作模式流程

1. **明确任务要素**：体裁、场合、受众、篇幅、时间节点、必须覆盖的内容点（用户给的素材清单）。要素不全先问，特别是：给谁看、什么场合用、有没有必须写进去的事项。
2. **选模板**：从 `结构模板.md` 选匹配当前体裁与场合的模板；没有匹配模板时，选最近似的并在交付时说明做了哪些变通。
3. **列信息大纲**：把用户材料拆成信息点，按模板的块位归置。信息点不足的位置留空待补，不虚构；交付时列出"待用户补充"清单。
4. **成稿**：
   - 结构按模板，分条样式与过渡句直接取用档案摘录的原文句式。
   - 用词对照 `语言DNA.md` 的高频词与套语清单、句长节奏、称呼自称。
   - 提法对照 `表述口径库`；涉及口径敏感点逐字使用档案摘录。
   - 排版对照 `排版规范.md` 的编号体系与标题风格。
   - 篇幅比例参照模板各块的占比。
5. **去AI味**：按 `anti-ai-tone.md` 白名单清理成稿（档案优先）。
6. **自检**：对照 `风格DNA.md` 最高优先级规则逐条核对；抽查三段与样文对读，检查语感是否一致；确认没有把样文内容搬进新稿。

## 三、改写模式流程

1. **盘点信息点**：通读原稿，列信息点清单（数字/日期/人名/事项/结论/表态等级），这是改写后的核对底稿。
2. **诊断偏离**：对照档案逐段标出四层偏离——语言层（用词、句式、节奏）、结构层（骨架、分条、过渡）、口径层（提法、表态等级）、排版层（编号、标题风格）。诊断结果决定改写深度：
   - 只有语言层偏离 → 局部改写，结构不动。
   - 口径层偏离 → 口径替换优先，其他从简。
   - 结构层明显不匹配 → 调整结构，交付时说明。
3. **逐段改写**：按档案重写，信息守恒（第一节）。逐段处理、逐段核对，不做全文一次性重排。
4. **去AI味**：按 `anti-ai-tone.md` 白名单清理。
5. **守恒核验**：信息点清单逐项对照（第一节核验办法）。
6. **交付说明**：简要列出——口径对齐了几处（各是什么）、结构调整了什么、语气强度有无调整、哪些段落原文材料稀薄只是按风格顺写了（如有）。

## 四、交付要求

- 新稿用 `YYYY-MM-DD 体裁 标题.md` 命名，放用户指定位置。
- 交付说明控制在十行以内，只列实质改动。
- 用户对某处改动有异议时，以用户意见为准并顺手更新档案：改写暴露出的口径或风格偏好（用户纠正过的）补进 `立场与认知.md` 或 `语言DNA.md`，档案越用越准。

## 五、自检清单

- [ ] 信息点清单逐项核对通过（数字、日期、人名、事项、表态等级无一丢失、无一新增、无一改变）
- [ ] 表态等级无升降（对照表态等级表）
- [ ] 口径逐字对齐（敏感提法与档案摘录完全一致）
- [ ] 称呼与自称符合档案体系，全文一致
- [ ] 标题编号体系符合档案（公文"一、（一）1.（1）"与论文"1. 1.1"未混用）
- [ ] 结构与模板匹配，过渡句式取自档案
- [ ] 句长节奏与样文对读无明显违和
- [ ] 去AI味白名单已过一遍，且未误伤档案特征
- [ ] 未把样文内容搬进新稿
- [ ] 交付说明已附
