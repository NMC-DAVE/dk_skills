# 文风DNA（写作风格提取与复刻）

## 一、这个 skill 做什么

两件事：

1. **提取**：从用户提供的样文（通常 2-10 篇：领导讲话、公文、论文、总结汇报等）蒸馏出一份"风格档案"。档案是可执行、可检查的风格规则集，每条规则都要有原文例证，不是"文风简练大气"这类读后感。
2. **复刻**：写作或改写前重新读取风格档案和样文原文，按档案成稿，最后用白名单规则清除 AI 痕迹。

与面向新媒体、要求从互联网抓取 20 篇以上文章的语料式蒸馏不同，本 skill 面向日常工作：语料以用户本地文件为准，数量可以很少，但每次提取必须附带"语料覆盖与置信度说明"，讲清哪些特征是多次观察到的事实，哪些是少量样本上的推断。语料不足时如实说明局限，不建议编补。

**根本原则：复刻的是写法，不是内容。** 样文中的具体数据、案例、成绩只作为风格样本，不自动搬进新稿，除非用户明确要求沿用。

## 二、三种模式

| 模式 | 典型触发语 | 做什么 |
| - | - | - |
| A 提取建档 | "分析这几篇文章的风格""给X建一个风格档案" | 第三节流程，产出档案目录 |
| B 按风格写作 | "按X的风格写一篇……""用这个档案起草……" | 第四节流程，产出新稿 |
| C 按风格改写 | "把这篇稿子改得像X写的""照X的口径改，去掉AI味" | 第五节流程，产出改写稿 |

用户只给了文件没说明意图时，先确认模式与目标体裁，不要自行猜测。模式 A 完成后主动告知：后续说"按X的风格写/改"即可直接进入模式 B 或 C。

## 三、模式 A：提取建档

### Step 1 收语料

- 接受 `.md` `.txt` `.docx` `.pdf` 等，非纯文本先转换为 `.md` 或 `.txt`，转换中丢失的格式要素（红头、印章、图表）在登记表中注明。
- 存入档案目录的 `raw/`。命名：`YYYY-MM-DD 体裁 场合或标题.md`；日期不详写"日期不详"。
- 档案目录默认建在当前工作目录下 `style-profiles/<来源名称>/`（如 `style-profiles/张书记/`），用户指定位置时以用户为准。完整结构见 `templates/style-profile/README.md`。
- 语料以用户提供为准。仅当用户明确要求且内容公开发表时，才联网补充收集，并把来源 URL 记入登记表。
- 数量与信心：
  - **≥5 篇**：正常提取，五层全做。
  - **2-4 篇**：正常提取，但认知层（立场与认知）的结论一律标注"推断"。
  - **1 篇**：只做语言层粗提取和结构照搬，向用户说明局限，建议再补 2-3 篇不同场合的文本。

### Step 2 登记语料

填写 `_meta/语料登记表.md`（一张表）：文件名 / 日期 / 体裁 / 场合与用途 / 受众 / 字数 / 结构要点 / 备注。这是跨篇对比和后续"选相似样文"的依据，不可跳过。

### Step 3 体裁判定

判断语料属于哪些体裁：领导讲话稿、公文（通知/请示/报告/函/纪要/批复）、学术论文、工作总结与汇报材料、评论文章、其他。读 `references/genre-guide.md` 的对应小节，确定各层提取重点。

多体裁混合（如同一位领导的讲话 + 签发的公文）：语言层与认知层合并分析；结构层与排版层按体裁分节，分别给出模板。

### Step 4 逐层分析

按 `references/analysis-guide.md` 的操作细则，产出四份分层产物：

| 产物 | 内容 | 回答的问题 |
| - | - | - |
| `语言DNA.md` | 用词、句式、称呼与自称、语气强度、标点习惯 | 句子怎么写 |
| `结构模板.md` | 按体裁分列的开头/主体/结尾骨架与过渡句式 | 文章怎么搭 |
| `立场与认知.md` | 议题侧重、价值排序、表述口径库、素材与引用偏好、核心命题 | 话怎么说、事怎么摆 |
| `排版规范.md` | 标题编号体系、标题风格、段落节奏、格式惯例 | 版面什么样 |

每条规则必须附原文例证（逐字摘自 `raw/` 并标注来源文件）。没有把握的宁可不写，或降级为"推断"。

### Step 5 整合风格DNA

把四份产物压缩成 `风格DNA.md`（单文档 ≤3500 字），作为写作前快速重读的总入口。内容是规则和示例，含四块：最高优先级规则（十条以内）、分体裁要点、禁用清单（该来源不会用的词、句式和表述）、置信度说明。

### Step 6 质量自检

- [ ] 每条规则能在 `raw/` 中指出至少 1-2 处出处
- [ ] 表述口径库覆盖语料中反复出现的固定提法；语料少时如实标注覆盖情况
- [ ] 结构模板覆盖语料中的全部体裁，每种体裁含过渡句式原文
- [ ] 排版规范含标题编号体系（语料可判断时）
- [ ] 置信度说明区分"确证 / 观察 / 推断"三级（定义见 `references/analysis-guide.md`）
- [ ] `风格DNA.md` ≤3500 字，无臆测、无形容词堆砌

## 四、模式 B：按风格写作

每次写作前必须完成读取步骤，不允许只凭 `风格DNA.md` 或上一轮对话的记忆下笔——整合文档是压缩结论，真实的语感只存在于分层产物和样文原文里。

1. **读全部档案**：`风格DNA.md` + 四份分层产物，一份不跳。
2. **读 2-3 篇最接近的样文**：按登记表的体裁和场合选，与本次任务最像的优先，语料 ≤3 篇时全读。读完要能说出这几篇的共同语感再动笔。
3. **明确任务要素**：体裁、场合、受众、篇幅、必须覆盖的内容点。缺要素先问用户。
4. **成稿**：结构取自 `结构模板.md` 中匹配的模板，用词与句式对照 `语言DNA.md`，立场与提法对照 `表述口径库`，排版对照 `排版规范.md`。内容点全部来自用户提供的材料，不得虚构数据、事例和引语。
5. **去 AI 味**：按 `references/anti-ai-tone.md` 白名单清理成稿。
6. **自检**：对照 `风格DNA.md` 的最高优先级规则逐条核对；检查口径无一处偏离；确认没有把样文内容搬进新稿。
7. 详细流程见 `references/rewrite-guide.md` 的写作部分。

优先级（冲突时取舍）：用户本次明确指令 > 风格档案中匹配当前体裁的部分 > 体裁硬规范 > 去AI味通用规则。档案与体裁硬规范冲突（如样文格式不合公文国标）时，默认按档案写，同时向用户指出冲突点。

## 五、模式 C：按风格改写

输入通常是一篇 AI 初稿、通用模板稿或他人代笔稿。流程：

1. **读档案和最接近的样文**（同模式 B 第 1-2 步）。
2. **盘点信息点**：列出原稿全部信息点（数字、日期、人名、机构、事项、结论、表态等级），改写后逐一核对，不能少、不能多、不能变。
3. **诊断偏离**：对照档案逐段标出语言层、结构层、口径层、排版层的偏离点。
4. **逐段改写**：按档案重写，信息守恒。表态等级和口径是红线（见 `references/rewrite-guide.md` 的表态等级表）。整体结构仅在明显不匹配且用户未禁止时调整，交付时说明改了什么。
5. **去 AI 味**：按 `references/anti-ai-tone.md` 白名单清理。
6. **交付**：附简要说明——口径对齐了几处、结构调整了什么、哪些地方原文材料稀薄（如有）。
7. 详细流程与信息守恒规则见 `references/rewrite-guide.md` 的改写部分。

### 临时校准（不建档的快速通道）

用户只给 1-2 篇样文、要求立刻写或改、不想等完整建档时：

1. 精读样文 2-3 遍，临场提炼 8-12 条要点：称呼与自称、句长与节奏、高频句式、口径提法、结构骨架、标题编号、语气强度。
2. 按要点执行写作或改写，其余流程同上。
3. 交付时说明这是临时校准，精度不如建档，建议之后补齐语料走模式 A。

## 六、边界

- 复刻写法不复刻内容。不冒充本人署名，不伪造数据、事例和引语。
- 涉密或内部文件只在本地处理，未经用户要求不通过任何联网工具传输其内容。
- 档案目录（含 `raw/` 样文）属于用户本地资产，不主动对外发布或上传。
- 表述口径、政策提法以语料原文为准，即使与 AI 的常识判断不一致也不"纠正"，拿不准时问用户。
