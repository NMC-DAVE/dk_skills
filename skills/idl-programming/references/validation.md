# 编译与最小测试

## 默认验证

先 `check` 方案文件，再 `run` 方案和无参数测试过程。测试过程调用真实入口，以小型合成数据断言结果；不只打印结果。对实际项目输入需要核对字段或维度时，读取最小必要样本。

```idl
pro test_example
  compile_opt idl2
  actual = mean([1d, 2d, 3d])
  if abs(actual - 2d) gt 1d-12 then message, 'mean assertion failed'
end
```

测试随任务调整：正常值、无匹配、全缺测、单元素或空值、形状错误等只覆盖相关分支。图形测试核对有效输出；数学结果需要手算值、性质或可信参考值，不能仅把实现再抄一遍作 expected。

## 进程行为

- 每次验证创建独立 IDL 进程，不连接已有交互会话。`check` 使用 `.compile`，不执行程序入口或主级代码。编译文件可包括辅助代码，按传入顺序处理。
- `run` 将入口名传给包装过程，用 `catch` 捕获运行时错误。参数与断言放在用户测试入口中。此命令会执行指定代码；其输出、文件副作用和所调用外部程序受该代码控制。
- 进程只临时添加 cwd、文件父目录和显式 `--include` 到 `!PATH`，不修改系统 PATH 或 IDL 持久配置。IDL 自身可能读取启动文件并写会话历史，环境输出单独保留。
- 成功要求完整输出标记、所有编译状态为零、无已识别的编译诊断、测试入口正常返回、进程成功退出且未超时。测试内部若吞掉错误，包装器无法证明正确性，仍需有效断言。
- 超时终止当前 IDL 进程并报告失败；测试代码不应启动额外后台进程。默认 60 秒，真实长任务需要明确增大限时。
- 目录经原生进程参数传递，编译使用相对文件名，避免 Windows IDL 管道输入的中文路径编码问题。非 ASCII 文件名复制到临时目录，以 ASCII 别名编译；原件不变，返回 `staged_sources` 对照。此时例程自查源码位置会指向临时副本，不能据此查找伴随数据文件；应从任务接口传入数据路径。路径/命令中的换行和 NUL 被拒绝；入口名不能包含任意 IDL 表达式。

## 失败与交付

先区分运行时发现、许可/启动、编译、运行、断言和环境历史写入错误。不能把权限或许可失败当作代码缺陷反复改写。主过程通过而结束阶段出现历史记录写入警告时，报告环境警告与代码验证结果。

在新建临时文件中修复可确定的问题，保持原始输入。检查 `ok` 及各阶段字段，保留必要诊断。没有实际执行、文档版本待核实或只有部分分支被测试时，在交付中简洁说明。
