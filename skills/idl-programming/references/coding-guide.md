# IDL 编码细则

按任务读取对应细则，并查阅所用例程的官方文档。这些规则改编自插件 IDL Agent 指令，不替代项目已有规范。

## 程序组织与语法

- 新函数与过程内写 `compile_opt idl2`，使用小写例程名、变量和关键词，系统变量保留官方表示，如 `!PI`、`!VERSION`。IDL2 采用 32 位默认整数并启用严格数组下标语法；明确需要双精度的计算使用 `double()` 或 `1d` 常量。
- 区分 `value = function(args, keyword=value)` 与 `procedure, args, keyword=value`。布尔关键词可写 `/keyword`，不要按 Python 的命名参数或布尔值语法推测。
- 方括号表示数组/下标；对象与结构的属性、方法、构造方式逐项核对文档。新对象优先直接构造 `classname()`。
- 文件名与可自动发现的例程名匹配；同文件的辅助例程定义在调用它们的例程之前。修改旧代码时保持其入口和接口。
- 多行使用 IDL 的 `$` 续行符；注释用 `;`。参数说明交代输入/输出、类型、维度、单位、可选值和缺测值。

## 数组与科学计算

- 先写清各维的含义与顺序；IDL 第一维变化最快，下标从 0 开始。对 `reform`、`transpose`、矩阵乘法和逐元素运算确认形状。不要推定 NumPy 广播、切片的半开区间或轴编号规则。
- `where(expr, count)` 无匹配时可能返回 `-1`，而 `-1` 会索引末元素。使用结果前检查 `count gt 0`，或按文档使用 `/null`。测试无匹配分支。
- 区分 `n_elements` 与维度查询；IDL 标量和单元素数组可能表现不同。确认空值 `!NULL` 与缺测数值的语义。
- 对平均、求和、插值、拟合等，核对精度、整数溢出、维度关键词和有效样本数。需要时先转换为双精度。
- 明确 NaN、有限值或业务缺测标记的处理方式；`/nan` 的行为按具体例程核对。全缺测、空输入、单样本不能依靠默认行为猜测。
- 大数组优先向量化；需要分块时说明内存与边界处理。不要为避免循环而改变数学定义。

## 文件与错误处理

- 使用 `filepath()`、`path_sep()` 或已有项目路径工具组合路径；输入输出位置来自用户或接口，避免硬编码机器路径。
- 文件读写、NetCDF/HDF 句柄与图形对象按对应 API 关闭或销毁；异常分支也需要清理。
- 可恢复的错误使用 documented `catch` / `message` 模式，报告有用上下文；不要吞掉异常后仍输出成功。测试断言失败应抛出 `message`。
- 编译不能保证调用存在或关键词合法；某些错误只会在运行相关分支时出现。

## 图形

- 新图形优先 `plot()`、`contour()`、`image()` 等 Function Graphics；时间序列、散点、误差、场图按数据含义选择例程。维护 Direct Graphics 代码时遵从原接口。
- 自动测试使用 documented 无窗口输出模式，例如相关图形例程的 `buffer`，并将图像保存至临时目录。核对 `.save` 的格式、文件存在与有效图像内容。
- 图形程序经命令行执行后进程会退出，用户若需要交互窗口，应明确安排其生命周期，不添加无界等待。
